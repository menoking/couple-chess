## 云同步与联机（可选）

不配置也能玩：24 个玩法默认纯本地。配置后才有「账号 + 题库云同步 + 双设备联机」。

### 一次性配置

1. 在 [Supabase](https://supabase.com) 新建项目
2. SQL Editor 整段执行 `supabase/fix-cloud.sql`（幂等、可重复执行；全新项目也可用 `supabase/schema.sql`）
   - 这一步**只影响题库跨设备同步**；不执行也能正常双设备联机
3. **必须关闭邮箱验证**：`Authentication` → `Sign In / Providers` → `Email` → 关掉 **Confirm email**
   （账号用的是「用户名@cfc.local」这种虚拟邮箱，收不到信，所以必须关）
4. Vercel → `Settings` → `Environment Variables`（勾选 Production）：
   - `VITE_SUPABASE_URL`：Supabase → Project Settings → API → Project URL（**不含** `/rest/v1/`）
   - `VITE_SUPABASE_ANON_KEY`：同页面的 **Publishable（anon）** key，不要用 Secret
   - 加完必须 **Redeploy**
5. 验证：首页右上角 ☁️ 点开出现用户名/密码输入框即成功

### 怎么用（没有邀请码）

1. 打开 ☁️ → 输入**用户名 + 密码** → 注册
2. 第二台设备用**同一个用户名密码**登录
3. 两台设备点**同一个玩法** → 房间 ID 固定为「账号 + 玩法」，必然是同一间，不需要房间码
4. **先开房的是房主，后来者无条件作为访客加入他的房间**，不会各自开一局；界面顶部标注「房主 / 访客」
5. 两台设备同时进入时按进入时间决胜，只会产生一个房主
6. 房主持续广播「我在玩」，另一台设备什么时候打开页面都能看到底部「一起玩」入口，点一下直接加入
7. 房主退出后，另一台设备退出该玩法再进一次即可接手当房主（会重新开局）

### 手机端「初始化小屋失败」/ 一直显示「正在初始化小屋…」

新版把「初始化小屋」改成了**纯本地操作**：登录成功就直接拿账号 ID 当小屋 ID，
不查表、不建屋、不等网络，所以这一步已经不可能失败。若手机上仍然看到旧提示：

1. 打开 ☁️ 看最底部的「诊断」行有没有 **版本 2**。没有 → 手机加载的还是旧构建：
   去 Vercel 重新部署（改过环境变量必须 Redeploy），再强制刷新页面。
2. 面板里「题库同步：失败」会直接给出中文原因，点「重试」可重新拉取。
   常见原因是 `space_data` 表缺失、旧外键未解除、RLS 策略不全 → 执行 `supabase/fix-cloud.sql`
   （末尾的 `notify pgrst, 'reload schema'` 会刷新 PostgREST 缓存）。
3. **题库同步失败不影响联机**：房间 ID = 账号 ID + 玩法，两台设备必然同一间。

旧版会卡住的四条路径都已移除：`spaces(id,name,invite_code)` 嵌套查询依赖 PostgREST
外键关系缓存、两台设备同时首次建屋撞唯一索引、非 HTTPS 页面里 `crypto.randomUUID()`
不可用导致非法 uuid、`onAuthStateChange` 回调没 catch 把数据库错误静默吞掉。

### 真机排查：连接诊断

打开 ☁️ 面板，最下面「连接诊断」会显示构建标识、云配置、账号/小屋 ID、设备 ID、
当前玩法是否支持联机、**上一次开局走了哪条分支及原因**、房间号/房主访客/连接状态、
以及最近 14 条事件日志（登录、开局、房间选举、订阅状态、视图同步）。点「复制诊断」
可直接把 JSON 贴出来比对两台设备。

关键判读：

- 没有 `diag-20261112-1` 构建标识 → 手机加载的仍是旧部署，等 Vercel 部署完再强刷。
- 「云配置 缺失」→ 该构建没有注入 `VITE_SUPABASE_*`，联机整块会被关闭。
- 「设备 dev-unknown」→ 两台手机用了同一个 Presence key，会双双当选房主。
- 「上次开局 直接同屏」→ 看括号里的原因（未登录 / 玩法不支持联机 / 构建缺配置）。
- 联机页顶部会显示房间号后 8 位与座位；**有房间号但棋盘空白** = 已进房、视图没同步，
  和「没进入房间」是两回事。

### 内置测试账号

面板里有一键按钮：**test / test1234**。首次点击会自动创建，之后直接登录。
它和普通账号一样拥有全部功能（本项目没有分级权限），只是多一个「测试账号」标记。

### 已支持联机

| 玩法 | 双设备后解决什么 |
|---|---|
| 吹牛骰 | 各看各的骰子，不用再传手机 |
| 九路围棋 | 各自全屏棋盘，落子实时同步 |
| 斗兽棋 | 同上，吃子与兽穴判定同步 |

### 联机抽卡规则

联机玩法同样会弹任务卡，和同屏版一致地写明「**抽卡 · 谁 → 执行 · 谁**」：

| 玩法 | 触发条件 | 抽卡人 | 执行人 |
|---|---|---|---|
| 斗兽棋 | 每吃掉对方一子 | 吃子方 | 被吃方 |
| 斗兽棋 | 终局 | 胜方 | 败方 |
| 九路围棋 | 每提满 3 子 | 提子方 | 对方 |
| 九路围棋 | 终局（连停两手 / 认输） | 胜方抽 2 张 | 败方执行 2 张 |
| 吹牛骰 | 开牌判负 | 赢家 | 输家 |

- 卡片内容由**房主设备的题库**写进权威对局状态，两台设备看到的是**同一张卡**，不依赖各自本地题库。
- 卡片会同时弹在两台设备上：**执行人**点「接受 / 跳过」确认，另一方只读等待，确认后两边一起关闭。
- 多张卡会依次弹出；卡片没确认前双方都不能继续操作，避免抢跑。
- 没选任务包时会退回到默认抽卡题库，不会出现「联机就没卡」的情况。

### 数据与隔离

- **一个账号一间小屋**：不同账号之间题库、战绩完全隔离
- **退出登录会清空本地对局数据**，避免下一个账号读到上一个账号的内容
- 无损迁移：旧键 `couples-ludo-game-state` 只读复制到 `cfc:` 命名空间，旧键保留可回滚
- 沙盒：URL 加 `?sandbox=1` 使用独立存储
- 备份：面板内可导出 / 导入 JSON

### 已知限制

- Supabase 免费项目连续 7 天不活跃会被自动暂停，需手动恢复
- 题库同步「后写覆盖」，请固定在一台设备上编辑
- 房间是常驻的（按 账号+玩法 固定），不是每局新建
