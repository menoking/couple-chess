# 情侣飞行棋 · 互动游戏合集

[![Deploy with Vercel](https://vercel.com/button)](https://vercel.com/new/clone?repository-url=https%3A%2F%2Fgithub.com%2Fmenoking%2Fcouple-chess)

专为情侣设计的互动游戏 Web 应用。

在线预览：[https://chess.menoking.top](https://chess.menoking.top)

## 玩法

**经典**：飞行棋 · 任务卡牌 · 扫雷 · 情侣转盘 · 姿势模式

**益智**：情侣 Bingo · 记忆翻牌 · 点格棋 · 数独 · 九路围棋 · 斗兽棋 · 拍卖竞价

**互动**：默契问答 · 限时挑战 · 吹牛骰

**剧情**：故事接龙 · 合作生存 · 领地争夺

**挑战**：真心话大冒险 · 赌局轮盘 · 高潮边缘 · 惩罚阶梯 · 翻牌赌命 · 角色扮演

## 云同步与联机（可选）

不配置也能玩：24 个玩法默认纯本地。配置后才有「账号 + 题库云同步 + 双设备联机」。

### 一次性配置

1. 在 [Supabase](https://supabase.com) 新建项目
2. SQL Editor 整段执行 `supabase/fix-cloud.sql`（幂等、可重复执行；全新项目也可用 `supabase/schema.sql`）
   - 这一步**只影响题库跨设备同步**；不执行也能正常双设备联机
3. **必须关闭邮箱验证**：`Authentication` → `Sign In / Providers` → `Email` → 关掉 **Confirm email**
   （账号用的是「用户名@cfc.local」这种虚拟邮箱，收不到信，所以必须关）
4. Vercel → `Settings` → `Environment Variables`（勾选 Production）：
   - `VITE_SUPABASE_URL`：Supabase → Project Settings → API → Project URL（**不含** `/rest/v1/`）
   - `VITE_SUPABASE_ANON_KEY`：同页面的 **Publishable（anon）** key，不要用 Secret
   - 加完必须 **Redeploy**
5. 验证：首页右上角 ☁️ 点开出现用户名/密码输入框即成功

### 怎么用（没有邀请码）

1. 打开 ☁️ → 输入**用户名 + 密码** → 注册
2. 第二台设备用**同一个用户名密码**登录
3. **登录态 = 联机态**：24 个玩法点「开始」一律自动进房，不再弹「同屏 / 联机」选择；
   首页也不再显示双方卡包选择（改到房间大厅里各自选）；**退出登录 = 单机态**，一切照旧在一台设备上玩
4. 房间 ID 固定为「账号 + 玩法」，两台设备点同一个玩法必然同一间，不需要房间码
5. 进房后先到**房间大厅**：两台设备各自勾选自己想玩的卡包 → 各自点「锁定我的卡包」→
   双方都锁定后自动合并去重成公共题库并开局；对方没上线时可点「先用我的卡包开局」
6. **性别开关只在登录态影响规则**：男方坐 0 号位、女方坐 1 号位，决定名字/颜色、先手、
   主题包归属与任务卡执行人；两台设备若选了同一性别，后进者自动调整为另一方并提示
7. **先开房的是房主（权威端）**，后来者无条件加入；房主负责裁决与跑计时器，界面标注房主 / 访客
8. 链路可靠性：Supabase 频道会**等 `SUBSCRIBED` 再发首包**，未订阅期间的座位消息先入队、订阅后补发；
   房主每 2.5 秒把局面补发给对方；访客进房前每 0.9 秒重发 `request-view`
9. 如果访客等待超过 8 秒（对方锁屏、退后台或已离开），连接页会出现「**我来开房（接管房间）**」，
   点一下由本机当房主，不会永远停在「正在连接房间」

### 手机端「初始化小屋失败」/ 一直显示「正在初始化小屋…」

新版把「初始化小屋」改成了**纯本地操作**：登录成功就直接拿账号 ID 当小屋 ID，
不查表、不建屋、不等网络，所以这一步已经不可能失败。若手机上仍然看到旧提示：

1. 打开 ☁️ 看最底部的「诊断」行有没有 **rules-20261113-3**。没有 → 手机加载的还是旧构建：
   去 Vercel 重新部署（改过环境变量必须 Redeploy），再强制刷新页面。
2. 面板里「题库同步：失败」会直接给出中文原因，点「重试」可重新拉取。
   常见原因是 `space_data` 表缺失、旧外键未解除、RLS 策略不全 → 执行 `supabase/fix-cloud.sql`
   （末尾的 `notify pgrst, 'reload schema'` 会刷新 PostgREST 缓存）。
3. **题库同步失败不影响联机**：房间 ID = 账号 ID + 玩法，两台设备必然同一间。

旧版会卡住的四条路径都已移除：`spaces(id,name,invite_code)` 嵌套查询依赖 PostgREST
外键关系缓存、两台设备同时首次建屋撞唯一索引、非 HTTPS 页面里 `crypto.randomUUID()`
不可用导致非法 uuid、`onAuthStateChange` 回调没 catch 把数据库错误静默吞掉。

### 真机排查：连接诊断

打开 ☁️ 面板，最下面「连接诊断」会显示构建标识、云配置、账号/小屋 ID、设备 ID、
当前玩法是否支持联机、**上一次开局走了哪条分支及原因**、房间号/房主访客/连接状态、
以及最近 14 条事件日志（登录、开局、房间选举、订阅状态、视图同步）。点「复制诊断」
可直接把 JSON 贴出来比对两台设备。

关键判读：

- 没有 `rules-20261113-3` 构建标识 → 手机加载的仍是旧部署，等 Vercel 部署完再强刷。
- 「云配置 缺失」→ 该构建没有注入 `VITE_SUPABASE_*`，联机整块会被关闭。
- 「设备 dev-unknown」→ 两台手机用了同一个 Presence key，会双双当选房主。
- 「上次开局 直接同屏」→ 看括号里的原因（未登录 / 玩法不支持联机 / 构建缺配置）。
- 联机页顶部会显示房间号后 8 位与座位；**有房间号但棋盘空白** = 已进房、视图没同步，
  和「没进入房间」是两回事。

### 内置测试账号

面板里有一键按钮：**test / test1234**。首次点击会自动创建，之后直接登录。
它和普通账号一样拥有全部功能（本项目没有分级权限），只是多一个「测试账号」标记。

### 统一规则层

`src/rules/` 是唯一的规则来源，24 个玩法共用同一套运行时，不再一个玩法写一份适配器：

| 文件 | 职责 |
|---|---|
| `types.ts` / `registry.ts` | 统一协议类型、24 玩法单一注册表、权威端独占计时状态 |
| `cards.ts` | 四阶段抽卡状态机、按座位裁剪卡面、把各玩法内嵌任务卡统一识别 |
| `identity.ts` | 性别 → 座位 / 先手 / 主题包 / 执行人映射，合并卡包主题 |
| `lobby.ts` | 双方各自选包 → 合并去重 → 双端锁定 |
| `room.ts` | 唯一 reducer + `viewFor`，房主按 seq 裁决 |
| `ModeRuntime.tsx` | `useModeState`：同屏 = `useState`（零变化），联机 = 共享快照 |

`useSharedRoom.ts` 负责房主权威状态与按座位下发；`OnlineStage.tsx` 复用**同屏那 24 个视图组件**，
只替换 props 来源，因此同屏与联机跑的是同一份规则代码，不会再出现规则分叉。

### 已支持联机

**全部 24 个玩法**（飞行棋、任务卡牌、扫雷、转盘、姿势、Bingo、记忆翻牌、点格棋、数独、围棋、斗兽棋、
拍卖、默契问答、限时挑战、吹牛骰、故事接龙、合作生存、领地争夺、真心话大冒险、赌局轮盘、高潮边缘、
惩罚阶梯、翻牌赌命、角色扮演）都进同一套房间运行时。隐藏信息（吹牛骰手牌）按座位隔离，
计时类由权威端独占跑表，避免两台设备各自推进。

需要完整规则的三处已与同屏共用同一份实现（`src/rules/modeRules.ts`，`useGameState` 也改成引用它）：

- **飞行棋**：逐格推进用 `calculateNewPosition`；踩到对方触发「亲密追尾」、幸运格/陷阱格按各自主题抽卡、
  48 格判胜；任务上的「前进/后退 N 格」在确认后落到执行人。
- **Bingo**：完成格子会重算 `lines`，连成一线时给出奖励任务并走统一抽卡。
- **扫雷**：翻到炸弹弹出「真心话 / 大冒险 / 主题任务」三选一，由对方指定、本人执行。

### 联机抽卡：四阶段锁定

所有玩法的抽卡都被 reducer 统一接管，卡面在权威状态里，按座位裁剪后下发：

| 阶段 | 胜方（抽卡人） | 败方（执行人） |
|---|---|---|
| `locked` | 看到「你赢了，来抽一张卡」按钮 | **锁定态**：锁图标 + 「等对方先抽卡」，拿不到任何卡面 |
| `drawn` | 已抽到并**看到卡面** | 卡背 + 「翻卡查看」按钮解锁，卡面仍未下发 |
| `revealed` | 双方同时看到卡面 | 点「接受 / 跳过」确认 |
| 出队 | 两端一起关闭 | 一起关闭，多张卡依次弹出 |

- 卡面在 `locked` 阶段对所有人下发 `null`，`drawn` 阶段只发给抽卡方；
  房主恰好是败方时，`viewFor` 同样裁剪，DOM 里不会出现任务明文。
- 卡片未确认前玩法操作全部锁定，防止抢跑。
- 卡包由两台设备各自选择后合并锁定，未选包时有兜底说明卡，不会「联机就没卡」。

### 数据与隔离

- **一个账号一间小屋**：不同账号之间题库、战绩完全隔离
- **退出登录会清空本地对局数据**，避免下一个账号读到上一个账号的内容
- 无损迁移：旧键 `couples-ludo-game-state` 只读复制到 `cfc:` 命名空间，旧键保留可回滚
- 沙盒：URL 加 `?sandbox=1` 使用独立存储
- 备份：面板内可导出 / 导入 JSON

### 已知限制

- Supabase 免费项目连续 7 天不活跃会被自动暂停，需手动恢复
- 题库同步「后写覆盖」，请固定在一台设备上编辑
- 房间是常驻的（按 账号+玩法 固定），不是每局新建
